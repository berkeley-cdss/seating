# Web Accessibility

Berkeley websites must meet [WCAG 2.1 AA](https://www.w3.org/TR/WCAG21/) (see Berkeley's
[Digital Accessibility page](https://dap.berkeley.edu/)). The `A11y` workflow checks every page of the
app against it on each push and pull request, following the approach of
[berkeley-class-site](https://github.com/berkeley-cdss/berkeley-class-site/blob/main/docs/a11y.md).

## What the tests do

`tests/a11y/test_a11y_pages.py` seeds the test database, starts the app, and opens every page in
headless Chrome, signed in as the kind of user who sees it (a student or a staff member). On each page it
runs [axe-core](https://github.com/dequelabs/axe-core) twice:

- `test_meets_wcag_21_aa` checks the `wcag2a`, `wcag2aa`, `wcag21a` and `wcag21aa` rules.
- `test_meets_wcag_22_aa` checks the `wcag22aa`, `best-practice` and `section508` rules.

Both must pass.

`test_every_page_is_audited` fails when a new page is added to the app but not to `PAGES` (or to
`SKIPPED_ENDPOINTS`, with a reason) in that file.

## Running them

```bash
pytest tests/a11y
```

You need Chrome installed. When a page fails, the test prints each broken rule with the elements that
break it, and the end of the run lists the pages for each rule. The full axe report for every page is
saved in `axe/`, with a screenshot of each failing page in `axe/screenshots/`. In CI, these are uploaded as
the `axe` artifact of a failed run.

## Exceptions

`SKIPPED_RULES` in `tests/a11y/utils.py` turns an axe rule off for every page, and elements marked
`data-a11y-errors="true"` are left out of every rule. Both are a last resort: fix the page if you can, and
keep an exception as small as possible, with a comment saying why.

## What the tests can't check

axe finds roughly a third of WCAG problems. Check these by hand when you change a page:

- Everything works with the keyboard alone, in a sensible order, with a visible focus outline.
- A screen reader (VoiceOver: <kbd>Cmd</kbd>+<kbd>F5</kbd>) announces controls and the seating chart
  sensibly.
- The page still works zoomed to 400% (or at 320px wide) without scrolling sideways.
- The contrast of text axe marks as "incomplete", such as dropdowns and seats in the seating chart.

Additionally, two staff pages aren't audited. The room import page and the master-sheet import page read from Google Sheets, which CI has no credentials for. These pages should be checked by hand via PR preview when edited.
